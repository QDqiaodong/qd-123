# 厂区安防布线配件存放分区归类系统

## 项目简介

工厂安防辅材档案与库房分区归类系统，支持配件建档（含**现存量**维护、**安全库存下限**设置）、自定义分区标签、配件分区调整（允许暂不分配分区）和按标签筛选。

布线方案管理支持按关键词、启用状态筛选，并可“导出当前筛选结果”为 CSV（UTF-8 BOM，Excel 可直接打开）。导出列为方案名称、适用场景、启用状态、配件名称、所属分区、需求数量、规格单位；同一方案的配件按库房分区排序号排列，方案信息逐行重复以保留方案边界；空结果、超长名称、中文文件名与导出中的重复点击均有明确处理（接口 `GET /api/wiring-plan/export`）。方案详情弹窗的配件分区与导出共用同一套排序（分区排序号升序、同分区按配件名称、未分配分区最后），刷新或编辑后顺序保持一致。

## 库存缺口与核销出库

- **现存量维护**：配件档案新增/编辑时维护现存量（非负整数），所有页面共用同一库存数据。
- **缺口合计**：菜单“库存缺口分析”（`GET /api/wiring-plan/stock-gaps`）按配件汇总需求数量，需求只统计**已启用且未核销**的方案；停用方案、已核销方案不参与合计。
- **现存量不足标红**：需求合计大于现存量的配件整行标红并显示缺口数量。
- **未分配分区单独列出**：未分配分区的配件在缺口列表底部单独成组（排序仍与方案明细一致，位于最后）。
- **按分区汇总**：缺口页提供“按分区汇总”表（`GET /api/wiring-plan/stock-gaps/zone-summary`），按分区汇总缺口件数与涉及配件种数（只统计现存量不足的配件，已删除配件不参与），未分配分区单独一行；表格底部合计行直接对分区小计求和。支持“导出分区汇总”为 CSV（`GET /api/wiring-plan/stock-gaps/zone-summary/export`，UTF-8 BOM），导出列为分区名称、涉及配件种数、缺口件数，末尾追加合计行；汇总与缺口明细同源归组，刷新后页面合计、分区小计与导出文件保持一致。
- **已删除配件**：配件删除为软删除，被方案引用时在方案明细与缺口列表中仍显示为“配件已删除”，但不参与缺口标红、不可核销出库；配件档案列表与方案配件下拉中不再出现。
- **核销出库（必须登记领料信息）**：方案列表/详情中点击“核销出库”会弹出领料对话框，**必须填写领料人与领料说明**才能确认（`PUT /api/wiring-plan/{id}/writeoff`，请求体携带 `receiver`、`remark`；纯空格视为未填，后端 Bean Validation + Service 双层强制校验）。关闭或取消对话框不发起请求、不产生任何核销记录；同一方案仍只能核销一次。
- **核销扣减与对账**：校验方案启用、未核销、无已删除配件且现存量充足后，在同一事务内按明细扣减现存量并写入核销记录（`stock_writeoff`，每方案唯一，含领料人、领料说明快照）。同一方案不可重复核销、不可再编辑或删除；扣减使用带条件的行级更新（`stock_quantity >= 需求`），并发核销不会扣成负数。刷新后方案的“已核销”标记、领料人/领料说明与已扣减的配件现存量同源一致（方案列表与详情接口均回填 `writeoffReceiver`、`writeoffRemark`），对账时可直接对应是谁领的、领去做什么。
- **一致性**：配件现存量、方案明细需求、缺口列表均取自同一套数据，刷新后配件档案、方案明细与缺口列表保持一致。

## 安全库存台账

- **设置安全库存下限**：配件档案新增/编辑时维护“安全库存下限”（非负整数，可留空）。留空（NULL）表示**不设下限、不纳入安全库存监控**；只有显式设置了下限的配件才会被台账评估。配件档案列表新增“安全库存下限”列，未设置显示“未设置”，现存量低于下限的在档案中直接标“待补货”。
- **独立台账**：菜单“安全库存台账”（`GET /api/accessory/safety-stock`）是与“库存缺口分析”相互独立的一张台账，只列**未删除、已设下限且现存量低于下限**的配件，列为名称、型号、分区、现存量、下限、缺口（缺口 = 下限 − 现存量）、规格单位。未设下限、现存量不低于下限、已删除的配件一律不进台账。
- **未分配分区不漏**：未分配分区的低位配件在台账底部“未分配分区”单独成组列出（排序与缺口列表一致：分区排序号升序、同分区按配件名称、未分配分区最后），不会因为没分分区而漏报。
- **改完即对账**：台账为实时计算，所有接口响应 `no-store`。在配件档案改下限或现存量、方案核销出库、分区盘点确认回写后，通过库存变更广播立即重算；刷新后台账条数与缺口合计与配件档案逐行对得上（把档案中所有“已设下限且现存 < 下限”的行求和即得台账）。
- **下限语义**：下限为 0 视为已设但永远不会低于（现存量非负），不会产生待补货；要停止监控请在编辑中点“清空（不设下限）”。

## 补货单

- **台账勾选生成**：安全库存台账每行新增勾选框，仓管勾选若干低于下限的配件（已在补货中的配件复选框禁用并显示占用单号，同一配件不能重复进单），顶部实时显示已勾选种数、缺口合计与**按分区汇总的缺口件数**。点“生成补货单”弹出确认框，先按分区汇总（分区排序号升序、未分配分区殿后）核对，可逐行微调补货数量（正整数、不得超过缺口），确认后生成**待提交草稿**并跳转到补货单页（`POST /api/replenish-order`，请求体 `items: [{ accessoryId, replenishQuantity? }]`，数量不传时后端按实时缺口“下限−现存量”补齐）。
- **服务端重新校验**：生成时不信任前端数据，按配件档案重新校验配件未删除、已设下限、现存确实低于下限、未被其他有效补货单占用；勾选后库存已被补齐或下限已清空的配件会被拒绝并提示刷新台账。
- **草稿可改可删**：待提交草稿在详情抽屉中可调整补货数量（`PUT /api/replenish-order/{id}/items`，可只改部分行、反复覆盖，不得超过生成时缺口），头表补货件数合计与分区小计实时重算；草稿**不占用**配件档案待补标记，也可直接删除（`DELETE /api/replenish-order/{id}`）。
- **提交回写档案并锁单**：点“提交补货单”（`PUT /api/replenish-order/{id}/submit`）在同一事务内把**补货单号与待补数量**回写到每个配件档案（`replenish_order_id/replenish_order_no/replenish_pending_quantity`），配件档案列表新增“补货中（单号/待补）”列，台账相应行显示“补货中 <单号>”并禁用勾选。提交用行级条件更新（`replenish_order_id IS NULL AND deleted=0`）抢占配件，并发提交两张单时只有一单成功，失败方整单回滚不留半单标记。**已提交单数量锁定**，后端拒绝任何改数量、删除或重复提交请求，前端也不渲染输入框。
- **作废清除待补标记**：已提交单可作废（`PUT /api/replenish-order/{id}/cancel`，可填写作废原因），同一事务内按单号清除全部配件档案的补货单号与待补数量，单据置为“已作废”只读留档。清除带 `replenish_order_id = 本单` 条件，不会误清后来新单的标记。作废后配件可再次生成补货单。
- **单号与状态**：补货单号 `BH + 时间戳 + 3 位随机数`（唯一索引 `uk_replenish_no` 兜底）；状态 0 待提交 / 1 已提交 / 2 已作废。补货单列表（`GET /api/replenish-order/page`）可按状态筛选，详情（`GET /api/replenish-order/{id}`）实时装配明细与按分区汇总，配件被删或被其他单占用时在详情标红（提交时整单拒绝并说明冲突配件）。所有接口响应 `no-store`，提交/作废后通过库存变更广播通知配件档案与台账立即刷新。

## 分区盘点

- **按分区开盘**：菜单"分区盘点"（`POST /api/stock-check`），选择一个分区标签或"未分配分区"开盘；**空分区和未分配分区也能开盘**（明细 0 种的盘点单照样保留留档）。开盘时把该分区下全部配件（**含已软删除配件**）带入盘点单，并快照账面现存量；同一分区同时只允许一张待确认盘点单（数据库生成列唯一索引 `uk_pending_zone` 兜底并发），已确认的历史盘点单不限数量。
- **登记实盘数与差异**：在盘点单抽屉中逐配件登记实盘数（`PUT /api/stock-check/{id}/items`），可部分登记、反复覆盖登记；差异按"实盘 - 开盘账面快照"实时计算并标盘盈/盘亏。**待确认期间不改动任何库存**，仅保存在盘点单内。
- **确认一次性回写并锁单**：全部正常配件登记齐全后点击"确认并回写"（`PUT /api/stock-check/{id}/confirm`），**必须先填写差异说明（`confirmRemark`，非空白、最长 500 字），纯空白说明不能点确认**（前端按钮禁用，后端 `@NotBlank` 与服务层双重校验）；提交后在同一事务内按实盘数一次性覆盖配件档案现存量（盘盈盘亏均可），并把盘点单置为已确认、差异说明随单持久化（提交前后端自动 trim）；**确认后单据只读，不可再登记、确认或删除**（条件更新 `status=0` 防并发重复确认）。
- **已删除配件只展示不回写**：开盘时已删除、或开盘后才删除的配件在盘点单中显示"已删除"标记，不要求登记实盘数，确认时跳过、绝不回写库存。
- **按有无差异说明筛选**：分页接口（`GET /api/stock-check/page`）支持 `hasRemark=true/false`，只在已确认单中筛"有说明/无说明"（纯空白视为无说明）；列表页"差异说明"下拉选择后自动锁定"已确认"状态，切回待确认/全部状态时该筛选自动清除。已确认单据的差异说明展示在列表列与详情抽屉中，**刷新后说明仍在**。
- **已确认单导出差异明细**：在已确认盘点单抽屉中点击"导出差异明细"（`GET /api/stock-check/{id}/diff-export`，UTF-8 BOM），导出列为配件名称、账面数、实盘数、盈亏件数（盘盈带 `+`、盘亏带 `-`）；只列盘盈/盘亏配件，账实一致与已删除配件不导出。无差异（含空分区、全部一致）时文件只有表头；有差异时末尾追加合计行，合计行的差异种数与盈亏件数与抽屉页面同源（`getDetailById` 实时装配），刷新后页面与导出文件一致。文件名 `盘点差异明细_<盘点单号>.csv`（RFC 5987 中文文件名 + ASCII 兜底名）。**待确认单不可导出**：前端按钮仅已确认单可见，后端也拒绝并返回"差异未定稿，请确认并回写后再导出"的原因。
- **刷新一致性**：确认成功后广播库存变更，配件档案、方案列表、库存缺口页立即按新现存量重算；所有接口响应 `no-store`，**刷新后配件档案现存量与最近一次已确认盘点结果一致**。已确认单据的账面快照永久保留开盘时数字，作为账实差异凭证。

## 整盘电源线建档（线缆盘）

- **按盘号建档**：菜单"整盘电源线建档"（`POST /api/cable-reel`），填写盘号、绑定配件与盘上剩余米数（非负整数）。盘号全局唯一，**同一盘号不能建两次**（先显式判重给出提示，数据库唯一索引 `uk_reel_no` 兜底并发）；绑定配件必须存在且未删除，配件名称、型号、单位在建档时快照。
- **建档窗取消不落盘**：建档对话框点"取消"或右上角关闭只关窗，不发起任何请求，这条盘不会落库；只有点"确认建档"并通过前端表单校验（盘号非纯空格、必选配件、米数非负）后才提交。
- **未开盘不入账**：建档后状态为"未开盘"，盘上米数只是登记，**不计入配件档案现存量**；列表中该盘显示"未开盘，未入账"，配件档案、缺口、台账均不受影响。未开盘盘可删除（`DELETE /api/cable-reel/{id}`）。
- **开盘确认一次性入账**：点"开盘确认"（`PUT /api/cable-reel/{id}/open`）后，在同一事务内把整盘剩余米数一次性加到绑定配件的现存量（米），并把盘置为已开盘、记录开盘时间；确认弹框取消则不开盘。开盘要求**该配件档案现存为 0**（整盘是其米数的唯一来源），否则拒绝并提示先清零或改绑——这样入账后"盘上剩余 == 配件档案米数"才恒成立。同一配件同时只允许一个已开盘（显式判重 + 数据库生成列唯一索引 `uk_open_accessory` 兜底，该索引仅对已开盘取配件ID，未开盘盘恒为 NULL 不占名额），并发开盘由唯一索引抢占兜底，失败方事务回滚、米数不入账；已开盘盘不可重复开盘、不可删除。
- **盘上剩余与档案米数一致**：开盘后列表同时显示"盘上剩余"和"配件档案米数"并给出"一致/不一致"标记（`stockMatched`，仅对已开盘且配件正常的盘判定）。重新进入页面（刷新）时该标记实时重算：开盘时档案为 0、扣米两边等量同步，正常联动下二者恒等；一旦因盘点回写等外部调整使配件档案米数偏离盘上剩余，会红色标出"不一致"，扣米入口同时拦截，要求先核对档案。
- **扣米（只有开过的盘能扣）**：已开盘盘点"扣米"（`PUT /api/cable-reel/{id}/deduct`），扣减米数必须为正且不超过盘上剩余；同一事务内用带条件的行级更新同步扣减盘上剩余（`remaining_meters >= 扣减`）与配件档案现存量（`stock_quantity >= 扣减`），并发扣米不会扣成负数，任一失败整体回滚，刷新后两处米数仍一致。**没开过的盘（未开盘）不渲染扣米入口，后端也强制拒绝**"尚未开盘确认，不能扣米"；绑定配件已删除或档案米数不足时同样拒绝。
- **库存联动广播**：开盘入账与扣米成功后通过库存变更广播通知配件档案、库存缺口、安全库存台账等页面立即按最新现存量重算；其他页面盘点回写改动档案米数后，线缆盘列表也会重拉以刷新"一致/不一致"标记。所有接口响应 `no-store`。

## 光纤熔接接头登记

- **仓管单独建账**：菜单“光纤熔接接头登记”（`POST /api/fiber-splice`），单独登记**接头编号、所属分区、盘留米数、是否过 OTDR**（另含备注）。接头编号全局唯一，同一编号不能登记两次（先显式判重给出提示，数据库唯一索引 `uk_splice_no` 兜底并发）；所属分区必须是存在的分区标签，分区名称登记时快照。新登记接头一律为“不可投运”。
- **列表按分区筛**：列表（`GET /api/fiber-splice/page`）可按**所属分区**筛选，另支持接头编号关键词、是否过 OTDR、可投运状态、在档/作废筛选；默认只列在档接头。
- **未过 OTDR 不能标可投运**：接头通过 OTDR 后在列表单独“标记可投运”（`PUT /api/fiber-splice/{id}/commission`，请求体 `commissionable`）。**OTDR 未过的接头前端“标可投运”按钮禁用，后端 Service 再次强制拒绝**“尚未通过 OTDR，不能标记可投运”，双层校验保证“可投运 ⇒ 已过 OTDR”恒成立；已标记可投运的接头不能在编辑中把 OTDR 改成未过（需先取消可投运标记）。
- **编辑**：在档接头可编辑所属分区、盘留米数、OTDR 结果与备注（`PUT /api/fiber-splice/{id}`），接头编号一经登记不可改。
- **作废只留档，不许物理删除**：作废（`PUT /api/fiber-splice/{id}/void`，可填作废原因）只把状态置为“已作废”并记录作废原因/时间，**记录行永久保留、系统不提供任何物理删除入口**；作废后接头只读，不可再编辑、标记可投运或重复作废。列表把档案状态筛为“已作废”即可随时查档。

## 辅材送检单

- **按已建档配件送检**：菜单“辅材送检单”（`POST /api/inspection-order`），仓管从**已建档、未删除**的配件下拉中选择送检配件，并必须写明**送检批次**与**实验室名称**。批次或实验室任一为空白（纯空格同样视为未填）都不能提交：前端表单禁用/拦截，后端 Bean Validation（`@NotBlank`）与 Service 层 trim 兜底双层强制；配件不存在或已删除时服务端重新校验拒绝。提交时快照配件名称、型号、规格单位，送检单号 `SJ + 时间戳 + 3 位随机数`（唯一索引 `uk_inspection_no` 兜底）。
- **新建即待回样**：送检单创建后状态为**待回样**（`sample_returned=0`），没有回样结论。待回样单只提供“写回结论”入口，列表回样结论列显示“待回样后写回”。
- **实验室写回结论**：实验室检测完成后仓管在列表点“写回结论”（`PUT /api/inspection-order/{id}/result`，请求体 `labConclusion`），**回样结论必填**（纯空白不能回样，前端按钮禁用 + 后端 `@NotBlank` 与 Service 双层校验）；写回成功后单据变为**已回样**（`sample_returned=1`）并记录回样时间。回样结论随单持久化，**刷新后结论仍在**；结论只能写回一次，已回样单重复写回由条件更新 `sample_returned=0` 拒绝。
- **未回样不能标合格**：已回样单才能点“标合格”（`PUT /api/inspection-order/{id}/qualify`，请求体 `qualified`）。待回样行不渲染标合格按钮，后端 Service 再次强制拒绝“尚未回样，实验室写回结论前不能标记合格”，条件更新 `sample_returned=1` 兜底并发，保证“**合格 ⇒ 已回样**”恒成立。已标记合格的单可“取消合格标记”（合格时间一并清空），回样结论与已回样状态不受影响。
- **按是否已回样筛选，刷新后保留**：列表（`GET /api/inspection-order/page`）支持按**是否已回样**（`sampleReturned=0/1`）、合格状态与送检单号/配件名称关键词筛选。是否已回样等筛选条件保存在浏览器本地，**刷新页面后自动恢复并按原条件查询**；“重置”清空全部筛选。所有接口响应 `no-store`，回样/合格操作后列表重拉，回样结论与状态取数据库最新值，刷新后仍在。

## 技术栈

- 前端：Vue 3、Vite 5、Element Plus、Axios
- 后端：Spring Boot 3、JDK 17、MyBatis-Plus、Maven
- 数据：MySQL 8、Redis 7
- 部署：Docker Compose、Nginx

后端、前端、MySQL、Redis 由 Docker Compose 统一编排。首次或依赖变化后执行：

```bash
docker compose up -d --build

```

## 常见问题

- Docker 拉取镜像慢：调整 `.env` 的 `DOCKER_REGISTRY` 或 Docker daemon 镜像加速。
- 数据库初始化异常：确认 `mysql/init` 脚本存在且数据卷状态符合预期。
- 页面接口失败：build 链路通过后，继续检查后端 API、代理和容器健康状态。
